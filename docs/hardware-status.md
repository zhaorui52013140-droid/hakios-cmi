# 硬件状态清单（Xiaomi Mi 10 Pro / cmi，iOS 16.5 on SM8250）

> 最后核实：**2026-11-19**
> 判定原则：只有**实机实测通过**的项才写成"可用"。驱动初始化成功、日志无报错，不等于硬件可用——本项目早期曾把 `bluetoothd` 起来当成蓝牙可用，实际耳机不出声。

分级含义：

| 级别 | 含义 |
|---|---|
| ✅ 可用 | 实机验收通过，有可复现的验收证据 |
| ⚠️ 有条件 | 能工作，但有明确缺陷或副作用 |
| ❌ 未实现 | 协议/驱动只到中间阶段，用户侧功能不可用 |
| ❓ 未验证 | 没有可信验收证据，不要假设可用 |

| **显示（AMOLED 1080×2340）** | 60 Hz 输出，桌面可见，背光可控；GL 每帧 68 次调用 / 12 次绘制 |
| **GPU（Adreno 650）** | `THE GPU BLOCK IS ALIVE`；GMU 时钟计数正常；zap shader 通过 TrustZone 验签；GL 绘制与桌面合成正常 |
| **触摸（FTS521）** | 每次启动均注册 `touch screen service`，扫描模式序列完整走完 `0x1fe → 0x101 → 0x1 → 0`；桌面可点按 |

## 2. 有条件可用（⚠️）

| 硬件 | 现状 | 缺陷 |
|---|---|---|
| **蓝牙 A2DP 音频** | 能连、能出声 | **持续卡顿**。根因已定位：蓝牙 UART 主机与控制器两端都被钉在 115200 baud，物理上限约 92 kbps，而 SBC 立体声需 229–345 kbps。3.2 Mbaud 的改造尚未成功（详见 `docs/ENGINEERING.md` §19–§21） |
| **震动马达** | 振动可被驱动 | 驱动运行后会**把音频留在关断锁存态**（iOS 重启不恢复，需进一次 Android 重新初始化功放）。引脚编号经 Android 设备树核对无误，怀疑是 TLMM 基址（`0x0f000000` vs `0x0f500000`）导致误写功放使能脚。**在查清前不要启用** |

## 4. 未验证（❓）

以下**没有**可信验收证据，请勿假设可用：

- 前置 / 后置相机、闪光灯
- 加速度计、陀螺仪、距离传感器、环境光
- GPS / GNSS（定位服务未打通）
- NFC
- 屏下指纹、Face ID
- 麦克风、通话听筒、有线 / USB‑C 音频
- 实体音量键、电源键的 iOS 功能映射
- 无线充电、反向充电、PD 高功率协商

## 附：如何自己验收

每一项的原始日志与命令都记在 `docs/ENGINEERING.md`。要点：

```bash
# 取启动段完整日志（实时环缓冲抓不到早期驱动日志）
fastboot oem stop
fastboot get_staged boot.log      # 约 1.5 MB，含内核初始化全段

# 取当前运行状态
fastboot oem log                  # 实时，约 130 秒窗口
```

判定"可用"时请以**用户侧行为**为准（有声音、有画面、有振动、能联网），而不是驱动日志是否报错。
